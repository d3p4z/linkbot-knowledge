# Improving the trustworthiness of Javascript on the Web

## What This Is
This article introduces Web Application Integrity, Consistency, and Transparency (WAICT), a proposed system to enhance the trustworthiness of web applications, particularly those relying on in-browser JavaScript cryptography. It details mechanisms for ensuring code integrity, consistency across users, and transparency through logging.

## Why It Matters
It addresses a critical gap in web security by providing app store-like guarantees for web applications, crucial for sensitive uses like end-to-end encrypted messaging, LLMs, and cryptocurrency wallets, which are vulnerable to malicious JavaScript modifications.

## Key Points
- JavaScript cryptography is inherently less trustworthy than native app equivalents due to challenges in code distribution and integrity verification.
- WAICT aims to provide Integrity, Consistency, and Transparency (ICT) for web applications through mechanisms like Subresource Integrity (SRI) and Integrity Manifests.
- Transparency is achieved via hash chains and prefix trees managed by transparency services and validated by witnesses, creating auditable logs of website code changes.
- The system includes features like unenrollment cooldowns and extension cooldowns to prevent immediate malicious actions during security incidents.
- WAICT is designed to be extensible, potentially integrating with code signing solutions like WEBCAT, and considers alternative deployment models like blockchain for specific ecosystems.
