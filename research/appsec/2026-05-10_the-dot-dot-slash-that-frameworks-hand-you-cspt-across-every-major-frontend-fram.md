# The Dot-Dot-Slash That Frameworks Hand You: CSPT Across Every Major Frontend Framework

## What This Is
This research analyzes how eight major frontend frameworks (React Router, Next.js, Vue Router, Angular, SvelteKit, Nuxt, Ember, and SolidStart) handle URL decoding for path and query parameters. It identifies vulnerabilities that can lead to Client-Side Path Traversal (CSPT).

## Why It Matters
The research highlights that almost all major frontend frameworks have inherent decoding behaviors that can be exploited to bypass route guards and facilitate attacks like CSRF, open redirects, and ultimately XSS, by allowing traversal into API calls or sensitive resources.

## Key Points
- Client-Side Path Traversal (CSPT) exploits the way frontend frameworks decode URL parameters, enabling attackers to manipulate API calls.
- Different frameworks exhibit varied URL decoding pipelines for path parameters, query parameters, and hash fragments, leading to framework-specific exploitation techniques.
- Query parameters are universally decoded and pose a significant attack surface due to the lack of segment boundary restrictions.
- The research details specific vulnerabilities and safe sources within React Router, Next.js, Vue Router, Angular, SvelteKit, Nuxt, Ember, and SolidStart.
- The combination of CSPT with rendering mechanisms like `dangerouslySetInnerHTML` or `v-html` can lead to Cross-Site Scripting (XSS) vulnerabilities.
