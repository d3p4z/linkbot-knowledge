# The New MCP Specification: What Security Teams Must Prepare For

## TLDR
- **MCP Specification Update**: The Model Context Protocol (MCP) is moving to a stateless, enterprise-grade architecture on July 28, 2026, shifting security responsibility to developers.
- **Eliminated Risks**: Old risks like session hijacking, unsolicited server prompts, and weak authentication (moving to OAuth 2.1) are gone.
- **New Attack Vectors**: Statelessness introduces risks like workflow hijacking, client-controlled metadata abuse, header confusion, XSS in MCP Apps, and DoS via background tasks.
- **Developer Responsibility**: Security boundaries and state management are now up to application developers, not the protocol itself.
- **MCP Apps Risk**: Rich UI apps can lead to phishing and data theft via stored XSS, even within sandboxed environments.
- **Background Task Risk**: Long-running asynchronous tasks create a denial-of-service vector by consuming server resources after the client disconnects.
- **Action**: Security teams must treat all client input as untrusted and implement strict validation, encoding, and resource quotas.
