# The GitHub Actions Attack Pattern Your CI Security Scanners Miss

## What This Is
This article discusses a class of CI/CD vulnerabilities named Cordyceps, where attackers exploit chained GitHub Actions workflows that individually appear safe, bypassing traditional security scanners. It highlights how the composition of workflows, rather than individual file integrity, creates exploitable weaknesses.

## Why It Matters
This is critical for application security as it reveals a blind spot in common CI security tools, demonstrating how sophisticated supply chain attacks can compromise even seemingly secure build pipelines, potentially leading to widespread impact through trusted updates.

## Key Points
- Cordyceps is a CI/CD vulnerability pattern exploiting the composition of GitHub Actions workflows, specifically 'pull_request_target' and 'workflow_run'.
- Attackers can leverage command injection, code injection via 'actions/github-script', and cross-workflow privilege escalation.
- Traditional SAST/DAST scanners miss these vulnerabilities because each individual workflow file is valid, and the exploitation lies in their interaction.
- AI-generated workflows can exacerbate this issue by rapidly reproducing insecure patterns at scale.
- Mitigation involves preferring 'pull_request' over 'pull_request_target', never checking out untrusted code in privileged workflows, and governing trusted sources for pipeline components.
